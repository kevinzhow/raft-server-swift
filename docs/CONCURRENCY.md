# Concurrency boundaries

## Checked server transaction leaves

The server Stores use checked Mutex state, but a checked declaration alone does not approve every cross-owner call. Tasks claim/status previously accepted an arbitrary `channelDeleted` callback and invoked it inside the Tasks transaction. TaskChannelDeletionQuery now holds the actual Channels owner and performs only the existing `postableChannel(...).deletedAt != nil` read at the same transaction point. Missing and archived-only channels remain false. Row lookup, refusal priority, revision/status/assignee/event writes and the supplied time retain their order; the channel read is not moved to an earlier snapshot.

The current production graph has Tasks → Channels for this fixed query, Messages → OAuth for mirror/cursor commit, and Channels → OAuth for DM/role leaves. Inspection of all ten Channels owner files and their current binders found no Channels-held → Tasks path; deleteChannel releases Channels before orphan cleanup, and role notices release Channels before Messages. This describes the inspected graph, not arbitrary future callbacks or mutex borrowing. ServerMembershipQuery now replaces the two server-order callback signatures. It holds only the actual OAuth owner, reads at the same point under Channels, and preserves the separate orderedServerList nonempty check and locked second read. Membership add/remove/guest restoration, GET without writeback, PATCH versions and eight concurrent patches use actual records in unit/HTTP tests. ServerAdmissionQuery now removes the three admission callback signatures. Its only private dependency is the actual OAuth owner: no-cap skips holder reads; seat count and active agreement remain two separate OAuth locks at their original Channels transaction points. Refusal precedes audit/spend/remove, while membership insertion remains after Channels returns. Actual owner seeds retain eight-way final-use and 32-way/five-audit assertions, live agreement versions, email removal and HTTP refusal priority. This does not reserve a seat globally across owners. ThreadChannelCommand now replaces the final two generic thread factories with one fixed primary-channel write at the original Channels → OAuth point. Normal lookup still filters server/deleted rows and appends order; action-card lookup intentionally differs, does not append order, retains missing-carrier fallback and iterates the original joint slice while appending projections. Real primary/local records replace minted/counter factories in 32-way tests, sequential replay/joint/fallback and published HTTP replies. All seven inventoried Channels callback APIs are closed; this remains a path-specific lock graph, with no claim of exhaustive joint concurrency or future callbacks.

## Retained daemon declarations

The daemon-only targets are `RaftDaemonClient` and `RaftDaemon`. After the immutable errors, timer/HTTP completion boundaries, four mutable daemon models, notification/janitor lifecycles, immutable activity sink, progress state, actor-owned probe results, immutable managed tool, correlated reminder/delivery state and the standing-prompt clock boundary and two private completion gates, complete turn-token state, turn-summary ownership, Kimi lock-handle state, WalkBudget consumption, fetch-pool cache ownership and ModelLister task ownership moved to checked state or NIO confinement, 10 explicit unchecked declarations remain, all in `RaftDaemonClient`. This inventory records actual storage and call paths. It does **not** certify those declarations as safe exceptions.

The six checked errors retain their constructors and metadata: upload-stage failure, HTTP-status failure, chat-bridge timeout, provider materialization, migration-entry limit, and unavailable Node host. Their fields are immutable Sendable values. An `Error?` cause follows Swift's Error/Sendable contract; this does not independently prove the implementation of every possible unchecked cause.

## How to read the evidence

A lock must protect every access to the state it owns. Separately locked getters do not make a multi-field decision or a check/register/publish operation atomic. A timer cancellation is not a join with an already running callback. A callback map lock does not protect values captured by its subscribers.

Tests listed below were inspected during the inventory. Serial tests and fake clocks establish behavior, not arbitrary thread safety. Real networking or overlapping Tasks provide evidence for those exercised paths only. Several helpers have no production integration caller; no external serial owner is assumed for them.

## Checked timer and transport boundaries

[RuntimeChildGuard](../Sources/RaftDaemonClient/RuntimeChildGuard.swift) now uses one checked Mutex state machine and an ordered effect drainer. Timer generations are reserved before scheduling and rechecked when tokens return; duplicate, synchronous, stale, or uncancellable callbacks cannot resurrect handed-over work. Log/schedule/cancel/signal callbacks run outside the state borrow. Handover invalidates future work; a signal already admitted before handover is in flight and is not joined by it. Default cancellation remains a no-op, and a permanently blocked injected callback can occupy its drainer. There is currently no production construction site for this helper; the default-scheduler acceptance uses a real child and proves its helper behavior, not daemon runtime wiring. Its old implementation killed that handed-over child at ten seconds; the real regression and thirteen dedicated cases now pass.

[DaemonHTTP](../Sources/RaftDaemonClient/DaemonHTTP.swift) constructs and synchronously installs its non-Sendable ExchangeHandler on the owning NIO loop. All nine parser/deadline fields stay on that loop; Scheduled deadlines use SDK NIOLoopBound and generation checks. CompletionBox uses checked Mutex state and resumes one installed continuation outside the lock, including finish-before-install. CONNECT/header deadlines and post-header slow bodies retain their behavior. Nine real-network tests with ten parameter cases cover timeout/peer-close/lane separation and slow EOF/chunked Unicode bodies. The baseline failure was valid CRLF chunk-size parsing; its explicit CRLF trim is a separate adjacent repair. The previous done access mismatch was established by source inspection, not a claimed dynamic race or TSan report.

[RuntimeNotificationState and DispatchNotificationScheduler](../Sources/RaftDaemonClient/RuntimeNotificationState.swift) now use checked Mutex state. Registration reserves one generation before invoking the scheduler outside the lock. A returned token is published only to that generation; clear or takePending invalidates an unpublished registration and cancels its token when it returns. Callback admission checks the generation once under the owner lock, then invokes outside it. The timer remains occupied after firing until explicitly cleared. Clear publishes the complete pending/memo/contribution reset before cancellation can reenter; takePending preserves notice and contribution memos. The default scheduler claims or removes a Sendable callback under its Mutex and invokes or releases it outside that lock. Cancellation prevents later admissions but does not join a callback already admitted. The old implementation passed all fifteen original cases and failed eight deterministic registration/reset/stale-callback regressions with twenty-five assertions; all twenty-three cases pass after the change, including one real default timer. These are public-helper lifecycle tests with controlled scheduler interleavings, not TSan, thread-stress, stdin/socket or complete daemon wiring evidence. Direct default-scheduler cancel/claim and captured-object deinit overlap are supported by source review rather than dedicated runtime tests.

[RaftDisk.JanitorSchedule](../Sources/RaftDaemonClient/RaftDiskJanitor.swift) now uses checked Mutex state for the timer reservation, generation, admitted pass, stop and effect queue. One drainer performs timer registration/cancellation outside the lock; a returned token belongs only to its original generation, and a consumed or stopped registration is cancelled after it returns. Duplicate/stale callbacks cannot overlap passes or erase a later timer. Stop invalidates future admission/rearm but does not join an admitted pass or in-flight registration. An admitted Task retains the schedule across await as before; pending timer callbacks remain weak. A permanently blocked injected timer operation can occupy the drainer. The six original tests and two ownership/stop guards pass on the old implementation, while six deterministic lifecycle regressions fail; all fourteen pass after the repair with the default concurrent suite. Existing orderly fake-timer behavior remains covered. These controlled public-Timers interleavings do not establish actual daemon wiring, a real timer/disk-pass combination, or TSan evidence. WalkBudget and disk scan/deletion policy are unchanged.

The two private completion gates in ChatBridgeRequest and OarListModels now keep their one-shot Bool in a checked Mutex. One take atomically changes false to true; cancellation, continuation resume and scheduler effects stay at the original caller positions outside the borrow. Sixteen unchanged public request/status/timeout/listing/join cases pass before and after. The first unchanged baseline missed two Oar fixture scheduler-registration waits; both isolated cases and one unchanged full target retry passed, with original logs retained. This gate change does not claim to fix that fixture failure, prove simultaneous completion under TSan, or close the remaining ModelLister and DispatchDeadlineScheduler lifecycles.

## Checked mutable model boundaries

[SpawnFailureError](../Sources/RaftDaemonClient/SpawnFailureClassification.swift), [ProbeChildError](../Sources/RaftDaemonClient/OpenCodeModelsCommand.swift), [ProviderHTTPResponse](../Sources/RaftDaemonClient/ProviderRequestFetch.swift), and [OarInstallation](../Sources/RaftDaemonClient/RuntimeAccountUsageCollector.swift) now preserve public setters and identity with checked Mutex state. Spawn classification captures its root and direct cause separately, reuses the root snapshot for a self-cause, and keeps the original two-node depth and code-driven decisions. Probe catch paths use one payload snapshot; the baseline produced 1008 impossible status/error-message combinations while only one status field was changing. Installation collection samples kind/command once, then invokes the async reader outside the lock with the original object; subsequent reader-visible changes remain possible.

Provider text/clone capture one body value. Body replacement swaps and returns the retired Data from the Mutex, then uses withExtendedLifetime outside it. This matters for public bytesNoCopy Data: its custom deallocator must not run while holding the body Mutex. The old setter's real-thread acceptance timed out while that deallocator waited for a reader; the fixed setter releases outside, and the reader observes the replacement. All 36 dedicated model cases passed in normal Swift 6.4.1 execution. These snapshots do not make multiple independent setter calls a cohort transaction, or the root/cause graph one simultaneous snapshot.

RuntimeProgressState now keeps its four value fields in one checked Mutex, retaining each original operation and the distinction between stall age and literal last-event age. Separate getter combinations remain separate reads. ProbeGate's actor now stores Task<any Sendable, Error> values instead of the private unchecked Any ResultBox; all callers still await the shared task, release/clear precedes completion, FIFO slots and errors retain their order, and one key still requires the same result type. LegacyActivitySink is checked from its five immutable Sendable callbacks; sequence uniqueness and callback ordering remain the injected collaborators' contract. Fourteen unchanged result/clock/join/FIFO/failure cases pass before and after. Probe tests use checked observation counters/arrays instead of racing fixture reads; sleeps, timeouts and assertions are preserved. This is helper/compiler evidence, not daemon wiring or TSan.

ManagedMcpTool is checked from its ten immutable Sendable fields; arguments remain local dynamic input and transport/warning behavior is unchanged. ReminderInboxStore keeps item map and first-insertion order in one Mutex: pure mint validation stays outside, replacement never moves an existing item, and list reads both collections together. RecentDeliveryIds likewise keeps order/timestamps together through remember/reorder/evict and selected-ID lazy expiry, with original zero/negative bounds and backwards-clock arithmetic. Fourteen before/after helper cases pass, including 128 concurrent reminder replacements/list reads and 64 delivery remembers/cap checks against actual public results. No new callback/Any storage or private observer was added. These are helper/compiler proofs; no production construction site or TSan coverage is claimed. StandingPromptLedger now completes mkdir under its I/O lock, samples the foreign clock with no owned lock held, then constructs/serializes/atomically writes the record under the second I/O section. The immutable fields have checked conformance. The original implementation passed four existing tests and failed the new public-write case's three real-file assertions: the clock could not observe the nested writer, and the late nested record won after the clock deadline. All five cases now pass with the same bounded fixture and writer drain. Each record keeps its sampled time; overlapping clocks may overlap and final actual commit wins, including an older timestamp. No clock-serialization, monotonic timestamp or cross-instance read/plan/write transaction is promised. Read/plan/schema/errors and per-call mkdir→clock→serialization→atomic-write order remain unchanged; this is local helper evidence, not daemon runtime or TSan.

TurnTokenAccumulator now stores added/base/latest in one checked Mutex. The three public setters remain independent replacements; note borrows the complete fold and counts borrows the complete read/delta/fallback. The original four cases pass, while two new 256-way public-output cases exposed lost additions and mixed Codex snapshots on the original Source; all six pass after the change. Missing/nil/zero/negative values, provider aliases, first-base last requirements, later latest replacement, whole-added backwards fallback and trace omissions retain their behavior. The Codex concurrency case pre-seeds base0 and does not claim concurrent first-base election or a transaction across separate public setters. This is actual helper result evidence, not daemon wiring or TSan.

DaemonTurnSummaryTracker now owns its open-turn map through one checked Mutex and private Sendable value accumulators. Begin finishes/replaces the previous turn in one borrow; observe folds a complete filtered batch before writeback; send outcomes mutate/write back in one borrow; finish removes/projects once. Values are taken from the map and restored inside that same borrow so the map does not retain the old nested arrays/maps during mutation. Classifier/rules, first-action order, explicit and unmatched-call FIFO, total problem count versus the twenty stored entries, nil reply behavior and end-time floor stay unchanged. Five original-Source and final-v2 cases pass, including 256 joined updates followed by 256 finish contenders and one complete real summary. The old implementation already locked the complete operations; this is checked ownership evidence, not a new race repair or a benchmark. Mixed observe/finish and concurrent begin are outside that bounded case; no daemon wiring or TSan claim.

KimiRefreshLockHandle now holds its optional first-compromise reason in one checked Mutex. A nil check and first write share one borrow; each public getter remains a separate read, and an empty String is still a non-nil compromise reason. The original three real process/filesystem/monitor tests pass before and after. The entire KimiRefreshLock enum tail is byte-identical, preserving options, retries, mtime, monitor, callback and cleanup behavior. The original NSLock already protected the handle; this is checked storage evidence and does not certify the complete filesystem takeover protocol or a paired-getter transaction. WalkBudget now keeps entries/deadline/outcome in one checked Mutex. Public setters stay independent; only the internal fixed consumeEntries method makes subtraction a complete RMW. isExhausted preserves its outcome→entries early checks, releases state before sampling the foreign clock once, then compares the deadline read after callback return, with no added post-clock checks. Batch64 admission stays separate from consumption: overdraw and final-batch complete remain valid. DaemonFetchPool now owns shared/isolated/direct caches in one checked Mutex. Each original lookup→immutable dispatcher construction→insert and each key removal remains one complete borrow; proxy/key/timeout computations retain their earlier positions, including cache hits. The six original cache cases and nine real-network definitions (ten expanded wire cases) pass before and after, with unchanged test bytes: identity reuse, lane/timeouts, 404/500 retention, transport eviction, timeout/peer-close and slow bodies remain. ## Work still required

Reconnect/reporting lifecycles, dynamic JSON payloads, callback subscribers, storage capabilities, and the other retained declarations still need explicit ownership or checked state; their current declarations are not approved merely because the targets are daemon-only.

Changing a declaration to Mutex is sufficient only when it preserves the complete transaction, reference ownership, callback ordering, and cancellation protocol. Remaining NIO loop exceptions must be local to a proven loop transfer boundary. Keep this inventory aligned with actual changes and remove completed rows from the retained-declaration table.
